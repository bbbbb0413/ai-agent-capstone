## 고객 공지 문안 규칙

고객사 담당자가 읽는 공지다. 한국어로 3문장 이내, 평문으로 쓴다(목록·제목·번호를 붙이지 않는다).
공지 본문만 쓴다. "다음은 공지 초안", "검토 후 발송해 주세요" 같은 머리말이나 맺음말을 붙이지 않는다.

- 넣는 것: 영향받은 서비스와 시작 시각, 현재 상태, 다음 안내.
  - 정상화됐으면(`recovered`가 true) "정상화되었습니다"라고 쓰고, 다음 안내는 원인 분석 결과 공유로 한다.
  - 아직 회복되지 않았으면 조치 중이라고 쓰고, 다음 안내 시각을 구체적으로 적는다(예: "30분 안에").
- 빼는 것:
  - OpsLens 내부 처리: 도구 호출, 오류·실패한 내부 요청, 재시도, 발송 대기열, 에스컬레이션, 승인 절차, PR, 런북 조항 번호
  - 추측한 원인, 시스템 내부 용어(Agent, MCP, 체크포인트 등)
  - 고객사 식별자(`tenant-a`)와 지표 용어(p95, 에러율 수치, 조회 창). "주문 처리 지연", "예약 오류"처럼 이용자가 겪는 현상으로 쓴다
  - 이 규칙 문장 자체. "정상화되었을 경우", "안내 용도" 같은 지시 문구를 옮겨 쓰지 않는다
- 한글과 영문 서비스 이름 말고 다른 문자(다른 언어 단어)를 쓰지 않는다.
