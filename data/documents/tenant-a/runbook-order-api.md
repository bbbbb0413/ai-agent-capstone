# A사 order-api 서비스 런북

가상 데모 문서다. 실제 고객사 문서가 아니다.

장애 형태별 조치는 MSP 표준 런북(RB-STD-*)을 따른다. 이 문서는 order-api에만 해당하는 운영 방식과 주의 사항이다. 레플리카, 의존 대상, 용량 같은 구조 값은 서비스 목록을 본다.

## RB-A-01 운영 방식과 변경 절차

- A사는 GitOps로 운영한다. 레플리카 수, 이미지, 설정값 같은 원하는 상태는 A사 설정 저장소의 PR로만 바꾼다
- MSP가 만든 PR은 A사 담당 엔지니어가 병합한다. 병합되고 동기화가 끝나야 반영된다
- 파드 재시작은 원하는 상태를 바꾸지 않으므로 PR 없이 바로 실행한다

## RB-A-02 DB 관련 연락과 주의

- order-api의 DB(postgres)는 A사 DBA가 소유한다. DB 자체가 느리거나 장애면 앱 조치 전에 A사 DBA에게 먼저 연락한다
- 확장할 때는 레플리카 수에 커넥션 풀 크기를 곱한 값이 DB 연결 한도를 넘지 않게 한다

## RB-A-03 고객 공지 기준

- Gold 등급이므로 장애 인지 후 15분 안에 첫 공지를 보낸다
- 공지 문안에는 영향 범위, 현재 상태, 다음 안내 시각을 넣고 원인 추측은 넣지 않는다
