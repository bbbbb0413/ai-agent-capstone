# A사 order-api 장애 대응 런북

가상 데모 문서다. 실제 고객사 문서가 아니다.

## RB-A-01 DB 커넥션 풀 고갈

- 증상: 5xx 에러율 급증, 로그에 `HikariPool-1 - Connection is not available, request timed out` 반복
- 확인: 에러율이 오른 시각과 커넥션 대기(waiting) 수가 늘어난 시각이 같은지 본다
- 1차 조치: 커넥션 풀 크기를 20 이상으로 늘린다 (`adjust_pool`, size=20)
- 2차 조치: 1차 조치 후 5분 안에 회복되지 않으면 서비스를 재시작한다 (`restart`)
- 승인: 담당 MSP 엔지니어

## RB-A-02 응답 지연

- 증상: p95 응답시간 1초 초과
- 확인: 외부 의존(DB, 결제)의 지연 로그를 먼저 본다
- 조치: 원인이 외부 의존이면 고객사 공지를 먼저 보내고 담당자에게 에스컬레이션한다

## RB-A-03 고객 공지 기준

- Gold 등급이므로 장애 인지 후 15분 안에 첫 공지를 보낸다
- 공지 문안에는 영향 범위, 현재 상태, 다음 안내 시각을 넣고 원인 추측은 넣지 않는다
