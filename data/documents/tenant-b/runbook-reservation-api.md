# B사 reservation-api 장애 대응 런북

가상 데모 문서다. 실제 고객사 문서가 아니다.

B사는 클러스터를 직접 운영한다. 허용된 조치는 MSP가 Kubernetes API로 바로 실행한다.

## RB-B-01 외부 결제 API 지연

- 증상: p95 응답시간 1.5초 이상, 로그에 `payment API timeout` 경고 반복
- 확인: 지연이 결제 요청에만 몰리는지, 결제 대행사 상태 페이지에 공지가 있는지 본다
- 조치: MSP가 직접 고칠 수 없다. 고객사 공지를 보내고 결제 대행사 문의는 고객사가 진행한다
- 금지: 원인이 외부에 있으므로 파드 재시작은 하지 않는다

## RB-B-02 작업 스레드 고갈 (파드 멈춤)

- 증상: 에러율 급증, 로그에 `503 worker pool saturated` 반복, 작업 스레드가 오래 묶여 있음(`oldest worker blocked`)
- 확인: 최근 변경 이력에 이상 시작 직전 배포가 없는지 본다. 배포가 없으면 프로세스 내부 상태 문제로 본다
- 조치: 파드를 재시작한다 (`restart_pods`)
- 금지: 레플리카 확장과 롤백은 계약상 MSP가 할 수 없다 (계약서 제3조)

## RB-B-03 고객 공지 기준

- Silver 등급이므로 장애 인지 후 1시간 안에 첫 공지를 보낸다
- 외부 업체 원인이면 업체 이름은 밝히지 않고 "외부 결제 연동 지연"으로 적는다
